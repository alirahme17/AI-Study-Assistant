# Teleco-Tutor: Personalized AI Study Assistant 📡

Teleco-Tutor is a full-stack, multi-user web application that allows users to transform their personal study materials from Google Drive into an interactive AI-powered chatbot. It uses a sophisticated Retrieval-Augmented Generation (RAG) pipeline to provide accurate, context-aware answers based solely on the user's documents.

## \#\# Key Features

  * **Multi-User System:** Secure user registration and login with personal, isolated workspaces for each user.
  * **Dynamic Knowledge Base:** Users connect their own Google Drive folder, and the system automatically ingests all PDFs to create a custom knowledge base.
  * **Personalized RAG Pipeline:** Each user has their own vector database, ensuring that answers are generated only from their documents.
  * **Bring Your Own Key:** Users provide their own Gemini API key for secure and personalized access to the LLM.
  * **Interactive UI:** A polished, multi-page Streamlit application provides a seamless user experience from signup and configuration to the final chat interface.
  * **Real-Time Responses:** The chatbot streams answers token-by-token for a responsive and engaging user experience.
  * **Source Citations with Page Numbers:** Every claim is cited like `[1]`, and each answer lists the exact PDF and page it came from, with a preview of the passage.
  * **Multilingual Search:** Questions in English find French slides and vice versa (multilingual E5 embeddings; each database remembers the model that built it).
  * **Hybrid Search:** Combines keyword search (BM25, exact technical terms like "DSDV" or "RRTS") with semantic vector search, merged with Reciprocal Rank Fusion.
  * **OCR for Scanned PDFs:** Pages without a text layer (scanned exams) are read with RapidOCR and cached; citations mark them as scanned.
  * **Evaluation Suite:** 25 verified questions with gold pages; measures retrieval hit@k, citation accuracy, LLM-judged answer quality and refusal of out-of-scope questions (`backend/eval/`).
  * **Conversation Memory:** Ask follow-ups ("and what about its range?"). The question is rewritten into a standalone search query using the recent conversation, and the model sees the last few turns.

-----

## \#\# Tech Stack

  * **Backend:** Python, FastAPI, Uvicorn
  * **Frontend:** Next.js 16, React 19, Tailwind CSS 4, KaTeX, Supabase Auth
  * **AI/ML:** LangChain, Google Gemini (default `gemini-3.8-flash`, configurable), Sentence-Transformers (`intfloat/multilingual-e5-small`, English + French), PyMuPDF
  * **Database:** ChromaDB (Vector Store) + BM25 keyword index (rank_bm25)
  * **OCR:** RapidOCR (ONNX Runtime, no external install)
  * **APIs & Auth:** Google Drive API, Google OAuth

## \#\# Setup and Installation

### \#\#\# Prerequisites

  * Python 3.9+
  * Git
  * A Google account with a Google Cloud project.

### \#\#\# 1. Clone the Repository

```bash
git clone https://github.com/YOUR_USERNAME/teleco-tutor.git
cd teleco-tutor
```

### \#\#\# 2. Backend Setup

1.  **Navigate to the backend directory:**
    ```bash
    cd backend
    ```
2.  **Create a virtual environment and install dependencies:**
    ```bash
    python -m venv venv
    source venv/bin/activate  # On Windows: venv\Scripts\activate
    pip install -r requirements.txt
    ```
3.  **Generate Google Drive Credentials:**
      * Go to the [Google Cloud Console](https://console.cloud.google.com/).
      * Create a new project and enable the **Google Drive API**.
      * Go to "Credentials", create an **OAuth 2.0 Client ID** for a **Desktop app**.
      * Download the JSON file and save it in the `backend/` directory as `credentials.json`.

### \#\#\# 3. Frontend Setup

1.  **Navigate to the frontend directory:**
    ```bash
    cd frontend  # From the project root
    ```
2.  **Create a virtual environment and install dependencies:**
    ```bash
    python -m venv venv
    source venv/bin/activate  # On Windows: venv\Scripts\activate
    pip install -r requirements.txt
    ```
3.  **Initialize User Configuration:**
      * Copy the template: `cp config.example.yaml config.yaml` (on Windows: `copy config.example.yaml config.yaml`).
      * Set `cookie.key` to a long random string. Users are added automatically when they sign up.
      * `config.yaml` is git-ignored — never commit it.

> **Security note:** `credentials.json`, `token.json`, `.env`, `config.yaml` and everything under `workspaces/` contain secrets or personal data and are excluded by `.gitignore`. Never commit them.

## \#\# How to Run the Application 🚀

Run the backend and the web app in two terminals.

### Terminal 1: backend (FastAPI)

```bash
cd backend
source venv/bin/activate          # Windows: .\venv\Scripts\Activate.ps1
AUTH_MODE=dev uvicorn main:app --reload   # Windows: $env:AUTH_MODE="dev"; uvicorn main:app --reload
```

Useful environment variables:

| Variable | Meaning |
|---|---|
| `AUTH_MODE` | `dev` (local, no passwords) or `supabase` (default when `SUPABASE_URL` is set) |
| `SUPABASE_URL` / `SUPABASE_JWT_SECRET` | Verify Supabase sign-in tokens (secret only for legacy HS256 projects) |
| `CORS_ORIGINS` | Allowed frontend origins, default `http://localhost:3000` |
| `GEMINI_MODEL` | Answer model, default `gemini-3.8-flash` |
| `RETRIEVAL_MODE` | `hybrid` (default), `vector` or `bm25` |
| `EMBEDDING_MODEL` | Model for new indexes, default `intfloat/multilingual-e5-small` |
| `OCR_ENGINE` | `rapidocr` (default) or `none` |
| `FAKE_LLM` | `1` = offline demo answers that quote the sources (no Gemini calls) |

### Terminal 2: web app (Next.js)

```bash
cd web
npm install
copy .env.example .env.local      # macOS/Linux: cp .env.example .env.local
npm run dev
```

Open `http://localhost:3000`. See `web/README.md` for details.

> The original Streamlit app in `frontend/` still works in dev mode but is being replaced by `web/`.

## \#\# Usage

1.  Navigate to the Streamlit URL (`http://localhost:8501`).
2.  Go to the **Sign Up** page from the sidebar to create a new account.
3.  Return to the main page and **Log In**.
4.  You will be prompted with a **one-time setup screen**. Provide the URL of your Google Drive folder and your Gemini API key.
5.  Click "Build My Knowledge Base" and wait for the system to process your documents.
6.  Once complete, the app will reload, and you can navigate to the **Chat** page to start asking questions\!
7.  Click **Sources** under an answer to see which PDF and page each `[n]` refers to. Use **New chat** in the sidebar to start a fresh conversation.

> **Upgrading an existing knowledge base:** databases built before page-level indexing still work, but citations show only the file name. Click **Re-index my PDFs** in the sidebar once to add page numbers (no Google Drive access needed).
